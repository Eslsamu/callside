# Internal API contract

All runtime HTTP routes share the UI origin on a loopback server. GET /api/bootstrap returns Bootstrap (token per server process, hasApiKey, allowed answer models), and optional keyStorage {canRemember,saved,error?} when the desktop secure store is configured. Other API requests need X-Callside-Token. POST /api/key {apiKey,remember?:boolean} replaces the active key, optionally persisting encrypted ciphertext through the desktop keyStore injected into startServer. Omitting remember or setting it false removes any previous saved key. An empty apiKey clears both session and saved key. Responses contain {hasApiKey,keyStorage?}, never the key. Updates are serialized; failed storage operations preserve the previous active key. Environment key also supported, with a successfully loaded saved key taking precedence.

POST /api/answer takes AnswerRequest and streams SSE data: JSON AnswerEvent. Abort cancels provider. mode:auto uses a WAIT sentinel hidden from UI when model judges no intervention. demo:true provides deterministic, clearly marked local fixture responses without network.

WebSocket /api/realtime?token=...&source=mic|system authenticates token plus exact same-origin Origin. First client frame {type:'configure',model,language,prompt}. Server opens wss://api.openai.com/v1/realtime?intent=transcription, sends GA session.update with 24kHz PCM and turn_detection:null, waits for session.updated, then sends {type:'ready'}. Client then sends input_audio_buffer.append (base64 PCM16), input_audio_buffer.commit. Standard OpenAI transcription delta/completed/error/buffer.committed events forwarded. Session errors close the stream and are surfaced. No silent reconnection/lost audio.

POST /api/diarize accepts JSON {audio:base64 WAV, source, chunkId, timestamp, language, knownSpeakers?:[{name,audio}]}. References must have unique names speaker_1–speaker_4 and canonical 24kHz mono PCM16 WAV clips of 2–10 seconds. At most four are accepted; validation happens before upstream calls. Names and WAV data URLs are passed to OpenAI known_speaker_names and known_speaker_references. Returns {entries:TranscriptEntry[]}, with timestamp and optional endTimestamp in epoch milliseconds. Provider entries retain source + chunk ID + returned speaker label. Legacy diarized mode remains explicitly scoped per chunk.

In realtime mode, settings.backgroundSpeakers (default true) adds a secondary system-channel sink. It consumes continuous capture samples before VAD cropping; the main live sink is unchanged. Batches use settings.diarizationChunkSeconds, default 12, with up to two seconds overlap. Four clean 2–6-second voice references are retained only during capture. Reference-linked speaker IDs are session-local; unregistered voices keep chunk-local IDs. The worker reports onAttribution(SpeakerAttribution) and onAttributionStatus without emitting onTranscript or invoking fatal capture failure. Queues hold at most two waiting jobs; stale waiting batches are dropped, request failures pause background attribution, and stop cancels work after ten seconds. Raw clips are cleared on stop and never exported.

TranscriptReconciler retains raw live revisions and overlays attribution using captured turn intervals and ordered text alignment. It preserves live text, splits mixed-speaker turns, and stores turnId as the original live ID. Automatic hints compare turnId rather than fragment IDs, so label updates do not retrigger the same turn. Answer input includes attribution reliability (reference or chunk). JSON exports include labels and speakerAttribution status/batch metadata, with no raw audio or references.

src/audio/capture.ts exports async startCapture(settings:Settings, token:string, callbacks:CaptureCallbacks):Promise<CaptureHandle>. Calls native/browser getDisplayMedia for system source and getUserMedia for mic. Separate sources, AudioWorklet PCM16 24kHz client VAD. Realtime and diarized modes selectable. stop() flushes final speech, cancels tracks, drains pending transcriptions boundedly.

desktop/main.cjs boots built server via exported startServer({port:0,production:true}) -> {url,close}. Loads url in sandboxed window. Preload exposes window.callsideDesktop {onAnswer(callback):()=>void, setAlwaysOnTop(boolean):Promise<void>, platform:string}. Global CommandOrControl+Shift+Space sends callside:answer. Package scripts own build.

desktop/key-store.cjs uses async Electron safeStorage and atomic private-file writes. Startup restoration never exposes a read-key IPC method. The renderer uses the existing authenticated local HTTP key route. src/audio/reconcile.ts retains original transcript revisions in memory and builds a view that removes blank turns and optional near-simultaneous microphone echo copies. The filtered view is used by the transcript, answer context, and exports; disabling the filter restores the original nonblank entries. settings.filterMicrophoneEcho defaults to true for existing templates.

## Task model settings

`settings.model` accepts only `gpt-6-luna`, `gpt-6-sol`, `gpt-6.1-sol`, or `gpt-6-astra`. `reasoningEffort` accepts `none`, `low`, `medium`, `high`, `xhigh`, or `max`; Astra and GPT-6.1 Sol do not accept `none`. Invalid combinations are rejected before an upstream request. Saved unsupported model IDs migrate to Luna; switching to Astra or GPT-6.1 Sol normalizes `none` to `low`.

The Responses provider sends `reasoning: { effort: reasoningEffort }`. `fastMode: true` sends `service_tier: "priority"`, the SDK-supported alias for Fast processing; false explicitly sends `service_tier: "default"`. Availability and any processing downgrade are controlled by OpenAI. Fast is a request, not a latency guarantee. The default is Luna, no reasoning, Standard processing, and `maxOutputTokens: null` (model default). Null omits `max_output_tokens`; numeric custom limits are normalized to 64–32,768 tokens including reasoning. Existing saved numeric budgets are preserved. Server request timeouts (65 seconds), SDK timeout (60 seconds), and a 24,000-character visible stream guard remain.

Model capabilities and Fast pricing are documented in the official [Luna](https://developers.openai.com/api/docs/models/gpt-6-luna), [Sol](https://developers.openai.com/api/docs/models/gpt-6-sol), [GPT-6.1 Sol](https://developers.openai.com/api/docs/models/gpt-6.1-sol), [Astra](https://developers.openai.com/api/docs/models/gpt-6-astra), and [Fast processing](https://developers.openai.com/api/docs/guides/priority-processing) documentation. Live provider access is not exercised by repository tests.

## General tasks and stable reference context

HTTP field names `systemPrompt`, `context`, `question`, and `/api/answer` remain compatible. UI labels are Task instructions, Reference material, Command, and Run task. `shared/tasks.ts` owns general defaults, the Workshop preset, and the 100,000-character reference limit shared with validation. The UI keeps oversized text intact and blocks submission; the API rejects oversized references before provider work. Only exact legacy default instructions migrate. Preset selection explicitly changes task, automatic rule, and trigger source while preserving references and model settings.

`buildAnswerInput` separates stable `instructions` and `referenceMaterial` from dynamic `modeInstructions` and `input` (JSON containing `userCommand`, recent `callTranscript`, and `previousSuggestions`). The Responses provider sends developer instructions, user reference data with `prompt_cache_breakpoint: {mode: "explicit"}`, dynamic developer mode instructions, and user request data in that order. `prompt_cache_options` is `{mode: "explicit", ttl: "30m"}`. Stable prefix equality is preserved across modes/commands. Tests validate the request shape, not actual provider cache hits.

`settings.autoTriggerSource` is `system` (default and migration fallback), `mic`, or `either`. Automatic evaluation waits for finalized transcript segments, uses the original source/turn ID for duplicate suppression, and obeys the cooldown. Partial updates and background label changes do not reset a pending timer for the same turn. Manual requests can use reference material with no transcript and include available partial transcripts. Reference material is never trimmed by the recent-transcript limit.

Provider terminal events may contain `usage: TokenUsage`. SSE `done` and `skip` preserve it; JSON exports record completed request usage and skipped checks in `requestUsage`. No credentials, raw reference audio, or provider hidden reasoning are recorded. Usage for cancelled/failed requests may be absent. New session clears usage records.
